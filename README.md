# distributedTaskRunner

`distributedTaskRunner` — небольшой распределённый обработчик HTTP-задач, написанный на Go с использованием gRPC.

Клиент отправляет URL на сервер, сервер сохраняет задачу в очереди, а отдельные процессы-воркеры получают задания, выполняют HTTP GET-запросы и возвращают результаты. По ID задачи можно узнать её состояние, HTTP-код ответа, время выполнения и ошибку, если запрос завершился неудачно.

Проект предназначен для изучения gRPC, конкурентности в Go и базовых механизмов отказоустойчивости распределённых систем.

## Требования

- Go 1.27 или новее.
- Свободный TCP-порт `50051` на локальной машине.
- Доступ к HTTP-адресам, которые будут проверяться.

## Запуск без сборки

Из корня проекта. Сервер и воркер запускаются в разных терминалах.

### 1. Запуск сервера

```bash
go run ./cmd/server
```

Сервер слушает `127.0.0.1:50051` и хранит задачи в памяти.

### 2. Запуск воркера

```bash
go run ./cmd/worker
```

При запуске воркер проверяет состояние сервера через gRPC Health Check, после чего начинает получать задачи. В текущей конфигурации запускаются три конкурентных обработчика.

### 3. Отправка задачи

В третьем терминале:

```bash
go run ./cmd/client submit https://example.com
```

Пример вывода:

```text
Submitted task with id: 1
```

### 4. Получение результата

```bash
go run ./cmd/client get 1
```

Пример вывода после выполнения:

```text
Get task with id: 1
Task status: completed
URL: https://example.com
Task result:
    HTTP Status: 200
    Time spent: 150ms
```

Здесь `1` — пример ID. Используй ID, полученный при отправке своей задачи. Если воркер ещё не обработал запрос, результат пока будет недоступен.

## Сборка

### Windows

Из корня проекта:

```powershell
go build -o server.exe ./cmd/server
go build -o worker.exe ./cmd/worker
go build -o client.exe ./cmd/client
```

Запуск в отдельных терминалах:

```powershell
.\server.exe
```

```powershell
.\worker.exe
```

```powershell
.\client.exe submit https://example.com
.\client.exe get 1
```

Из корня проекта:

```bash
go build -o server ./cmd/server
```

Запуск в отдельных терминалах:

```bash
./server
```

```bash
./client submit https://example.com
./client get 1
```

## Команды клиента

```text
submit <url>    Добавить URL в очередь задач. Поддерживаются http и https.
get <task_id>  Получить статус и результат задачи по положительному ID.
```

Возможные статусы:

- `pending` — задача ожидает выдачи воркеру.
- `running` — задача назначена воркеру.
- `completed` — HTTP-запрос завершился с ответом сервера.
- `failed` — HTTP-запрос завершился ошибкой, например из-за таймаута или недоступности адреса.

## Восстановление задач

При назначении задачи сервер выдаёт воркеру lease на 30 секунд. Если результат не получен вовремя, фоновая проверка возвращает просроченную задачу в очередь для повторного выполнения.

Каждое назначение получает новый `AttemptID`. Это позволяет отклонять результаты устаревших попыток. Повторная отправка одинакового результата уже завершённой попытки обрабатывается идемпотентно.

## Ограничения

- Задачи и результаты хранятся только в оперативной памяти. После перезапуска сервера они теряются, а ID начинают выдаваться заново.
- Адрес сервера, количество обработчиков и идентификатор воркера сейчас заданы в коде.
- Соединения gRPC в локальной конфигурации используют insecure credentials, без TLS.
- Для задач используются HTTP GET-запросы; произвольные методы HTTP пока не поддерживаются.
